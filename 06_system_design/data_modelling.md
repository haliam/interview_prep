# Data Modelling

> **Purpose:** Data modelling interview reference — the three model levels (Conceptual, Logical, Physical) and the Entity Relationship Diagram (ERD).

## Conceptual Model

> "This data model defines **WHAT** the system contains. This model is typically created by business stakeholders and data architects. The purpose is to organize, scope, and define business concepts and rules."
>
> "An abstract and high-level representation of a software system that focuses on capturing key entities and relationships without getting into technical details."

---

## Logical Model

> "Defines **HOW** the system should be implemented regardless of the DBMS. This model is typically created by data architects and business analysts. The purpose is to develop a technical map of rules and data structures."
>
> "A more detailed and technical representation of a software system that defines classes, interfaces, and relationships required to implement the desired functionalities, considering functional aspects and business rules. Defines the structure of the data elements and sets the relationships between them."

---

## Physical Model

> "This data model describes **HOW** the system will be implemented using a specific DBMS. This model is typically created by DBAs and developers. The purpose is the actual implementation of the database."
>
> "The implementation-focused representation of a software system that describes the concrete implementation details, including data structure, functionality implementation, and hardware/software configuration. Describes the database-specific implementation of the data model."

---

## Entity Relationship Diagram (ERD)

> "Entity Relationship Diagram (ERD): a database design tool that provides a graphical representation of database tables, their columns, and inter-relationships. ERD is the most popular database design tool."
